- **Deliberately not restored** — `#32`'s negative arm through `_idle_skeptic_parked` /

  against the DECOY as well as the fixed tree. Root-caused rather than deleted: the
  wrappers now reach the ladder through `$(skeptic_gate_state …)`, and bash does not
  propagate errexit into a command substitution unless `inherit_errexit` is set — off by
  default (confirmed `inherit_errexit off`, bash 4.4.20 on this host) and unset throughout
  the suite. So on the decoy the derivation runs to completion inside the substitution and
  the wrapper answers normally. `#33`'s own arm-6d comment already said this. The property
  did not disappear, it moved: arm `6e` asserts it directly on `skeptic_gate_state`, where
  it **does** discriminate. Re-adding it at the wrapper level would install a guard that
  passes regardless of the code it reads — the exact failure mode the arm exists to
  prevent — so the file carries a comment explaining the omission instead.

   still goes red**, and that self-check is what makes a merge of two suites verifiable.

## SK-Q1 — a real fail-open defect, found by the skeptic, now fixed

**The skeptic was right and I had not considered it.** My equivalence work during the
rebase checked the *state domain* (`live/grace/stale/orphaned/absent/unclassified` each
producing the same answer through the delegation as inline on `main`). It never asked what
happens when the derivation produces **no state at all**.

`retire-preflight.sh` check 1b calls the shared gate through a command substitution, and
`$(…)` **contains** an abort. If the ladder dies mid-derivation (unbound variable under the
`set -u` the preflight already runs with, a half-written probe lib, a helper that exits),
the preflight survives with `sk_state=""` and a non-zero rc — neither `0` nor `orphaned`, so
it falls past both branches, past checks 2/3, and out as `safe=1`.

Reproduced independently (my own harness, not the skeptic's), fresh marker, reviewer
GENUINELY ALIVE in the mocked tmux, abort injected into the ladder:

| tree | result |
|---|---|
| `main`, clean | `rc=1 safe=0 … marker unresolved` |
| branch, clean | `rc=1 safe=0 … gate: live` |
| `main`, abort in `_idle_skeptic_orphaned` | `rc=1`, **no `safe=` line** → kill aborted |
| branch, abort in `skeptic_gate_state` | `rc=0 safe=1 … safe to retire` → **KILL AUTHORIZED** |

The refactor traded a fail-CLOSED default for a fail-OPEN one: pre-gate, the predicate ran
in the preflight's own shell, so its abort took the preflight down with it.
`_skeptic_gate.sh`'s stated invariant ("anything that merely failed to check lands in
`unclassified`") is enforced *inside* `skeptic_gate_state` and cannot police a failure *of*
it.

**Attribution — not caused by the rebase.** Reproduced at `cf1c2bd` (where the `$(…)`
structure arrives) and at `7ea2ca2`, the pre-rebase PR head. This is `#16`/`#19` code the
branch already carried; the rebase propagated it. `#32` is unaffected. **Consequence for
the `#19` decision: merging `#19` on its own carries this defect with it** — that is new
information for the operator's choice, and it argues against option (b).

**Fix** (`5cdac7e`), at both consumer sites — an unrecognised state normalises to
`unclassified`, the class that blocks:

```bash
case "$sk_state" in
    live|grace|stale|unclassified|orphaned|absent) : ;;
    *) sk_state=unclassified; sk_blocks=0 ;;
esac
```

Recognised states keep the gate's own rc, so no reachable behaviour changes and no test
churn. Applied to `monitor/ng` too — and not merely for symmetry: there an aborted
derivation reads as "not gated" and `ng` **refuses** the hand-off while `retire-preflight`
**allows** the kill, i.e. the two sites wrong in *opposite* directions on the same worker.
That is the DISAGREEMENT `_skeptic_gate.sh`'s header calls out as worse than either local
default being wrong.

**Evidence** — new arm `9e` in `test-retire-preflight.sh`: drives an aborting gate through
the check that kills, against decoy trees, reviewer alive; asserts exit 1 / `safe=0` /
never `safe=1`; carries its own **negative control** (same abort, guard stripped → asserts
`safe=1` returns), so it cannot pass on a tree where the abort never fired. Stripping the
guard: 80 passed/0 failed → 76/4. Other suites unchanged (tristate 28/28, ng-wrap-up ALL
PASSED, skeptic-channel 245/245).

**Reachability: no live trigger found**, by the skeptic or by me. Two routes I checked
beyond the skeptic's truncation sweep — `${1:?window required}` (unreachable; `win_name` is
resolved or `exit 3` before check 1b) and `_skeptic_gate_load_probe`'s
`source … 2>/dev/null` (stdout is **not** suppressed, so probe-lib stdout does corrupt
`sk_state` — but the rc still comes from the ladder, so it blocks). The fix was made
regardless: "I could not find a trigger" is not "there is none", and this is the code that
decides whether a live worker is killed.
